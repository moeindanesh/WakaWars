# AI-generated Honor Titles via OpenRouter

Honor Titles (the flavor label under each username) were derived deterministically from a user's achievement grants via a fixed achievement→title map in `honor-titles.ts`. We are replacing that map's *output* with a creative title generated by an LLM through OpenRouter, prompted with a hybrid signal (the user's achievement profile **and** raw coding stats).

To keep the leaderboard fast and cheap, titles are generated **once per day per user inside the existing background sync**, only when the user's input signal actually changed (we hash the inputs to skip no-op token spend), and the result is **cached in the database**. The leaderboard always serves the cached string and never makes an AI call in the request path. The deterministic resolver is **retained as a fallback** for users with no generated title yet and whenever the OpenRouter call fails.

The model is selected via env (`OPENROUTER_API_KEY`, `OPENROUTER_MODEL`) defaulting to a cheap small model; the API key is server-side only and never reaches the renderer.

The prompt is intentionally **fun and sarcastic**, and the signal is enriched with the **tools the user actually used** — the top languages, editors, and projects mined from the daily `status_bar/today` payload — so titles can name-drop a user's stack (e.g. "Vim Hostage", "TypeScript Apologist"). The single dominant language/editor/project is folded into the input hash, so a title also refreshes when a developer changes their main stack, not only when they cross a milestone.

Trade-off: we accept an external dependency, per-user token cost, and non-deterministic output in exchange for more creative, personalized titles. The risks are bounded by the daily-cache cadence (latency/cost off the hot path) and the deterministic fallback (availability). The achievement *write path* is kept alive to feed the signal even though the achievements UI is removed.
